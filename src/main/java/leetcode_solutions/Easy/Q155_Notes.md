# LeetCode #155 - Min Stack (最小棧)

## 📌 學習筆記 (2026/04/23)

### 1. 核心觀念：輔助棧 (Auxiliary Stack)
*   **問題**：一般的 Stack 只能看到最頂端元素，無法立刻知道全場最小值。若只用一個變數存 `min`，當最小值被 `pop` 掉後，電腦會「忘記」之前的最小值是誰。
*   **解法**：使用兩組 Stack **同步操作**，就像是幫最小值「寫日記」。
    - `dataStack`: 儲存所有 push 進來的原始資料。
    - `minStack`: 儲存「到那一刻為止」的全場最小值。

### 2. 操作邏輯圖解
假設輸入順序：`5, 3, 7, 2`

| 操作 | DataStack | MinStack (最小值日記) | 說明 |
| :--- | :--- | :--- | :--- |
| Push 5 | [5] | [5] | 第一次，5 是最小 |
| Push 3 | [5, 3] | [5, 3] | 3 < 5，3 是新的最小 |
| Push 7 | [5, 3, 7] | [5, 3, 3] | 7 > 3，目前的最小依然是 3 (同步紀錄) |
| Push 2 | [5, 3, 7, 2]| [5, 3, 3, 2] | 2 < 3，2 是新的最小 |
| Pop | [5, 3, 7] | [5, 3, 3] | 同步拿走 2，日記翻回前一頁，最小變回 3 |

### 💡 Takahiro 的深度提問彙整

#### A. 建構子初始化 vs. 欄位初始化
*   **疑問**：為什麼不直接 `private Stack dataStack = new Stack();`？
*   **解答**：雖然語法可行，但將 `new` 放在 **建構子 (Constructor)** 內才是專業做法。這能確保物件在「出生」那一刻被正確設定，且未來若需要參數化初始化（例如指定容量）會更靈活，也符合物件導向的職責分配原則。

#### B. Stack 操作三兄弟：peek() vs pop() vs top()
*   **pop()**：拿走最上面的盤子，你會少一個元素。
*   **peek()**：只看最上面的盤子，但不拿走。
*   **top()**：在 LeetCode 此題中，其功能等同於對 `dataStack` 進行 `peek()`。

#### C. 魔力來源：toString() 覆寫
*   **現象**：原本印出 `minStack` 只會看到地址，覆寫後能看到 `Data: [-2, 0] | Min: [-2, -2]`。
*   **原理**：所有的 Java 物件都繼承自 `Object`。覆寫 `toString` 就是告訴 Java：「以後別印地址了，改印我指定的內容」。我們在裡面調用了 Java 內建的 `Stack.toString()`，借用了 Java 工程師寫好的排版魔力。

#### D. 神祕的 Integer Cache (-128 ~ 127) ✨
*   **觀念**：Java 的 `int` 範圍很大 (±21億)，但為了省錢（記憶體），會預先快取 `-128 到 127` 的數字。
*   **影響**：
    - 比對 `10 == 10` 會是 `true` (都來自同一個快取倉庫)。
    - 比對 `129 == 129` 會是 `false` (都是現場新建的物件，位址不同)。
*   **金律**：比對物件內容時，**務必使用 `.equals()`** 而非 `==`。

### 🛠️ 程式碼實作重點
```java
public void pop() {
    // 關鍵：如果拿掉的數字剛好是當前最小，日記也要跟著翻頁
    if (dataStack.pop().equals(minStack.peek())) {
        minStack.pop();
    }
}
```
