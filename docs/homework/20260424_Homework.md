## 📝 考核對答細節

### 🟢 Java OOP 部分

**Q1：記憶體模型：`Patient p1 = new Patient(); Patient p2 = p1;` 執行後 Heap 與 Stack 的狀態？**
*   **Takahiro 的回答**：Heap 只有 1 個 Patient 物件，Stack 兩個引用 p1、p2 都指向 p1 的地址。
*   **導師解析**：✅ **完全正確**。精確掌握了引用指向的觀念。

**Q2：封裝：為什麼不直接把 salary 設為 public？**
*   **Takahiro 的回答**：如果寫成 public 代表著任何人都有權利去改動它的值。
*   **導師解析**：✅ **正確**。這能保護資料完整性，且日後若要增加驗證邏輯（如：薪資不得超過十萬）只需修改 Setter，不需改動外部代碼。

**Q3：建構子：定義了「有參建構子」但沒寫「無參」時，執行 `new Patient()` 會發生什麼事？**
*   **Takahiro 的回答**：會出現類似這個錯誤訊息：`The constructor is undefined`。
*   **導師解析**：✅ **完全正確**。一旦手寫了建構子，編譯器就不再提供預設的無參建構子。

**Q4：Static：靜態方法裡面可以呼叫非靜態屬性嗎？**
*   **Takahiro 的回答**：因為 static 是共用的，不用特別 new。
*   **導師解析**：✅ **正確**。延伸觀念：Static 載入時物件可能尚未存在，所以它找不到實體屬性。

**Q5：Constructor Chaining：在建構子中使用 `this(...)` 時，這行必須放在哪？**
*   **Takahiro 的回答**：無參數、有參數、全參數建構子都可以吧。
*   **導師解析**：⚠️ **提醒**：`this(...)` 呼叫必須位於建構子的 **「第一行」**！

### 🔵 SQL 進階部分

**Q6：LEFT JOIN 與 INNER JOIN 的差別？**
*   **Takahiro 的回答**：Left JOIN 為左表跟右表交集以及左表的所有資料；INNER JOIN 抓共同資料。
*   **導師解析**：✅ **正確**。這是 SQL 聯結的核心觀念。

**Q7：什麼時候會建議使用「子查詢」而不是「JOIN」？**
*   **Takahiro 的回答**：不曉得，是同一張表中 有延伸其他欄位時需要？
*   **導師解析**：💡 **解析**：通常用於需要「先算出一個中間值」（例如：最高分、平均值）作為過濾條件時。

**Q8：UNION 兩邊的查詢結果限制？**
*   **Takahiro 的回答**：欄位數量需一致，型別也要一樣。ORDER BY 只能出現在最後一個。
*   **導師解析**：✅ **完全正確**。

**Q9：如何查詢「掛號費高於全院平均掛號費」的患者姓名？**
*   **Takahiro 的回答**：題目出不好沒有給我 table 和欄位。
*   **導師解析**：✅ **正確（笑）**。邏輯上需先用 Subquery 算出 `AVG(掛號費)`，再放到主查詢的 `WHERE` 條件中。

**Q10：合併巨大資料表且不需去重，用 UNION 還是 UNION ALL？**
*   **Takahiro 的回答**：UNION ALL，因為重複的資料會保留。
*   **導師解析**：✅ **正確**。且效能更佳，因為省去了去重所需的排序開銷。
