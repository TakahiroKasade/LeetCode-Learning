## ☕ Java 基礎篇解析

### Q1：外圈 i=3 時，內圈跑幾次？
- **你的回答**：3次 (❌)
- **正確解答**：**9次**
- **深度解析**：在巢狀迴圈中，外層每前進一格，內層都會「從頭到尾」跑完所有條件。就像時鐘的時針跳一格，分針必須跑滿 60 分鐘一樣。

### Q2：System.out.println() 誤放進「內層迴圈」？
- **你的回答**：就會逐筆分行！ (✅)
- **深度解析**：`println` 代表 Print Line。放在內圈會導致每個乘法結果都強迫換行，原本 9x9 的方陣會變成一條長長的 81 行垂直線。

### Q3：sum 變數宣告在迴圈內會怎樣？
- **你的回答**：不會累加，sum 永遠為 0。 (✅)
- **深度解析**：變數的作用域 (Scope) 很重要。若宣告在裡面，每次迴圈開始都會重新初始化為 0，導致之前的累加結果被抹除。

### Q4：判斷 x 是否為 3 的倍數？
- **你的回答**：`if (x%3 == 0 )` (✅)
- **深度解析**：完全正確。取餘數運算子 `%` 是工程師判斷倍數、奇偶數的最強工具。

### Q5：sum = sum + 1 跑 100 次的結果？
- **你的回答**：100 (✅)
- **深度解析**：邏輯正確。這題考驗的是你對「迴圈次數」與「累加動作」的對應關係。

## 🗄️ SQL 實戰篇解析

### Q6：SQL 中將 OR 改成 AND，資料會變多還是變少？
- **你的回答**：會變多 (❌)
- **正確解答**：**會變少**
- **深度解析**：
    - `OR` (聯集)：只要滿足「其中一個」條件就過關 -> 門檻低，資料多。
    - `AND` (交集)：必須「同時滿足」兩個條件才過關 -> 門檻高，資料少。

### Q7：SELECT * 與 SELECT product_id 的效能差異？
- **你的回答**：SELECT product_id 較佳，因為只查一個。 (✅)
- **深度解析**：專業！`SELECT *` 會增加資料庫 I/O 負擔、傳輸頻寬，且容易抓到不需要的雜訊。

### Q8：找 recyclable 不等於 'Y' 的條件？
- **你的回答**：`where recyclable != 'Y'` (✅)
- **深度解析**：正確。在標準 SQL 中，`!=` 或 `<>` 皆可代表不等於。

## 🧩 演算法思考篇解析

### Q9：Two Sum 暴力法中，j 為什麼從 i + 1 開始？
- **你的回答**：雙指針原理，left 跟 right。 (⚠️ 部分偏移)
- **深度解析**：
    - 在「暴力法」中，`j = i + 1` 是為了避開「同一個數字重複加兩次」（i=0, j=0）的情況。
    - 同時也保證了我們只往後找，不會重複比較已經算過的組合（例如比過 2+7 就不必再比 7+2）。

### Q10：如何解釋時間複雜度 $O(n^2)$？
- **你的回答**：100 筆資料要查 100*100=10000 次。 (✅)
- **深度解析**：這個量化說明非常直觀！適合跟非技術人員解釋效率低下的原因。
