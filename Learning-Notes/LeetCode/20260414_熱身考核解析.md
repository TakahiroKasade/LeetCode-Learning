## 🧩 演算法與邏輯

### Q1：在 #1 (Two Sum) 中，為什麼要把數字存進 HashMap？
*   **關鍵字**：時間複雜度、空間換時間。
*   **解析**：
    *   **暴力法 (Brute Force)** 需要兩層迴圈，$O(n^2)$。
    *   **HashMap** 的 `containsKey` 與 `get` 在平均情況下的時間複雜度是 **$O(1)$**。
    *   透過 HashMap 儲存「已見過的數字」及其「索引」，我們只需要遍歷一次陣列 ($O(n)$) 就能找到答案。

### Q2：在 #167 中，如果 `sum < target`，為什麼是移動 `left` 而不是 `right`？
*   **關鍵字**：雙指針 (Two Pointers)、有序陣列。
*   **解析**：
    *   因為題目給定的是**升序排序**陣列。
    *   `left` 向右移會指向更大的數 ➔ `sum` 增加。
    *   `right` 向左移會指向更小的數 ➔ `sum` 減少。
    *   當 `sum < target` 時，我們需要一個更大的總和，因此必須移動 `left`。

### Q3：如果題目沒有說陣列已排序，還能用雙指針法嗎？
*   **解析**：**不可以**。
    *   雙指針法能預測 `sum` 的變化方向（增大或減小）完全基於「排序」這個前提。
    *   若陣列是亂序的，移動指標無法保證總和會按預期變化，此時必須使用 **HashMap 補數法**。

## ☕ Java 程式語言

### Q4：在 Java 中，如果不判斷 `containsKey` 就直接 `map.get()` 會怎樣？
*   **關鍵字**：NullPointerException (NPE)、Auto-unboxing。
*   **解析**：
    *   `map.get(key)` 若找不到對象會回傳 **`null`**。
    *   在 Java 中，如果您將此回傳值存入 `int` 基本型別（例如 `int index = map.get(...)`），Java 會進行「自動拆箱」。
    *   對 `null` 進行拆箱會直接拋出 **`NullPointerException`**。這是在面試與實戰中常見的系統崩潰原因。

## 🗄️ SQL 資料庫

### Q5：在 SQL 中，找出「重複出現」Email 的關鍵字組合？
*   **關鍵字**：`GROUP BY`、`HAVING`、`COUNT`。
*   **語法示範**：
    ```sql
    SELECT email
    FROM users
    GROUP BY email
    HAVING COUNT(*) > 1;
    ```
*   **解析**：
    *   `GROUP BY`：將相同的 Email 歸類為同一組。
    *   `HAVING`：**專用於分組後的篩選**，在此用來找出現次數超過 1 的組別。
