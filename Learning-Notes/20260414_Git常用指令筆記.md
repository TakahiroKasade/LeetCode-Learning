這份筆記記錄了在本專案中常用到的 Git 指令，幫助您掌握版本管控的核心技巧。

---

## 🛑 特殊清理指令 (重點！)

### `git rm --cached <file>`
*   **用途**：解除追蹤，但不刪除實體檔案。
*   **使用時機**：當您不小心把 `target/` 或 IDE 設定檔上傳到 GitHub，想要從遠端移除它們，但本地開發還想留著檔案時。
*   **搭配動作**：執行完後，請記得將該檔加入 `.gitignore`，否則下次 `git add .` 又會把它抓回來。

## 🔄 每日標準工作流

### 1. 查看狀態 (必做)
```bash
git status
```
*   **解析**：確認有哪些檔案被修改了（紅色），哪些已經準備好要提交（綠色）。

### 2. 加入暫存區
```bash
git add <file>  # 加入特定檔案
git add .       # 加入本目錄下所有變更
```

### 3. 提交變更 (正式存檔)
```bash
git commit -m "feat: 描述您的新功能"
git commit -m "docs: 修改文檔"
```

### 4. 查看歷史
```bash
git log --oneline -n 5  # 查看最近 5 筆簡單紀錄
```

## 🛡️ 救命指令 (後悔藥)

### 恢復誤刪的檔案
```bash
git restore <file>
```
*   **解析**：如果您不小心把代碼寫壞了或誤刪，只要還沒 commit，都可以用這個指令從上一個版本救回來。

## 📝 我們的 Commit 規範
根據 `gemini.md`，我們使用以下前綴來保持紀錄整潔：
*   `feat:` 新增功能 (例如：完成一題 LeetCode)
*   `fix:` 修復問題
*   `docs:` 只有文檔變動 (例如：更新學習計畫)
*   `refactor:` 重構代碼 (例如：今天的大搬家)
