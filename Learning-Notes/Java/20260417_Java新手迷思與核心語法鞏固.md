## 🔍 迷思一：方法參數命名一定要跟 main 一樣嗎？
**問題描述**：在 `main` 裡的 Map 叫 `roomMap`，但傳入方法時參數名叫 `map`，這兩個是同一個嗎？

### **💡 核心觀念：遙控器原理 (Pass by Reference)**
*   **本質**：`HashMap` 是存在記憶體裡的「實體物件」（像是電視機）。
*   **標籤**：`main` 方法裡的 `roomMap` 只是這台電視機的一個「遙控器標籤」。
*   **傳遞**：當你呼叫方法時，你只是把「遙控器複製一份」交給方法。
*   **自訂暱稱**：方法在接過這個遙控器時，可以給它一個它喜歡的暱稱（參數名），例如 `map`。
*   **結果**：無論暱稱叫什麼，按下的按鈕控制的都是「同一台電視機」。

> [!TIP]
> **結論**：命名不一定要一樣。方法內的參數名通常會取更通用的名字，以便重複利用。

## 🔑 語法二：為什麼 `keySet()` 總讓人覺得抽象？
**問題描述**：`keySet()` 是什麼？為什麼還要套 `for` 迴圈？

### **💡 核心觀念：字典檢索 (Set of Keys)**
*   `Map` 本身是「成雙成對」的（Key-Value），無法像清單那樣直接從頭走到尾。
*   **`keySet()`** 的作用：它把 Map 裡所有的 **「標籤 (Key)」** 通通抓出來，裝進一個叫 `Set` 的盒子裡。
*   **遍歷邏輯**：
    1.  拿到標籤清單 (`keySet`)。
    2.  用 `for` 一個一個拿標籤。
    3.  拿到標籤後，再回頭去 Map 裡面「查表」(`get(key)`) 找出內容。

## ⚠️ 語法三：String 比較的致命陷阱
**問題描述**：為什麼 `if (docName == "Takahiro")` 可能會失效？

### **💡 核心觀念：內容 vs 位址**
*   **`==`**：在 Java 中，這是在比兩個東西是不是「同一個物件」（比對記憶體地址）。
*   **`.equals()`**：這是在比兩個字串的 **「內容文字」** 是不是一模一樣。
*   **實務準則**：在 Java 中，**只要是比較字串內容，一律使用 `.equals()`**！

---

## 🔄 語法四：HashMap 的覆蓋規則
**問題描述**：如果存入重複的 Key 會發生什麼事？

*   **Key (鍵)**：具有唯一性。存入重複的 Key 時，**舊的 Value 會被新 Value 覆蓋**。
*   **Value (值)**：可以重複。多個 Key 可以對應到同一個 Value。
