# Java 資料結構實務選用指南：Array vs. ArrayList vs. HashMap

在企業級 Java 開發中，選擇正確的資料結構是效能與可維護性的基石。本文件將深入探討 Array、ArrayList 與 HashMap 的實務應用場景。

---

## 1. Array (靜態陣列) —— 效能與穩定的象徵

### 💡 核心特性
- **固定大小**：初始化後長度不可變。
- **記憶體連續**：對 CPU 快取友好，存取速度極快（$O(1)$）。
- **類型安全**：可儲存 Primitive Types (int, double) 或 Objects。

### 🏢 企業實務場景：固定維度或效能優先
適合用於「已知數量上限」且「變更頻率極低」的底層資料。
- **案例：HTTP 狀態碼映射表**
- **案例：固定維度的矩陣運算（如 3D 渲染、科學計算）**

### 💻 範例程式碼
```java
/**
 * 場景：系統支援的工作日類型 (Fixed Context)
 */
public class ConfigConstants {
    // 使用陣列儲存固定不變的內容，效能最優
    public static final String[] WEEKDAYS = {
        "Monday", "Tuesday", "Wednesday", "Thursday", "Friday"
    };

    public void printConfig() {
        // 直接透過索引存取，不需要額外的方法開銷
        System.out.println("First working day: " + WEEKDAYS[0]);
    }
}
```

## 2. ArrayList (動態清單) —— 業務邏輯的骨幹

### 💡 核心特性
- **動態擴容**：大小不固定，會自動處理容量增長。
- **順序保證**：元素存入的順序會被保留。
- **彈性操作**：內建強大的 API (add, remove, clear)。

### 🏢 企業實務場景：頻繁增刪、CRUD 操作
絕大多數從資料庫讀取出來的清單數據，首選都是 ArrayList。
- **案例：電子商務購物車 (Cart Items)**
- **案例：資料庫分頁查詢結果 (Page Results)**

### 💻 範例程式碼
```java
/**
 * 場景：電子商務購物車處理 (CRUD Resource)
 */
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {
    private List<String> items = new ArrayList<>();

    public void addItem(String productName) {
        items.add(productName); // 動態新增，不需煩惱大小
    }

    public void processOrder() {
        // 遍歷所有訂單項目，ArrayList 遍歷效能僅次於 Array
        for (String item : items) {
            System.out.println("Processing: " + item);
        }
    }
}
```

## 3. HashMap (鍵值對映射) —— 查詢效率的終極武器

### 💡 核心特性
- **快速查找**：平均搜尋時間複雜度為 $O(1)$。
- **Key-Value 結構**：適合建立關聯。
- **無序性**：存入與取出的順序不保證一致（除非使用 LinkedHashMap）。

### 🏢 企業實務場景：快取、關聯資料查找
當你需要根據「唯一標識符」擷取資料，且資料量龐大時，HashMap 是唯一選擇。
- **案例：使用者 Session 管理 (Token -> UserInfo)**
- **案例：資料查找優化 (例如 LeetCode Two Sum 解法)**

### 💻 範例程式碼
```java
/**
 * 場景：員工資料快速查找 (Data Cache)
 */
import java.util.HashMap;
import java.util.Map;

public class EmployeeService {
    // 以員工 ID 作為 Key，員工姓名作為 Value
    private Map<Integer, String> employeeCache = new HashMap<>();

    public void preloadData() {
        employeeCache.put(101, "Takahiro");
        employeeCache.put(102, "Bob");
    }

    public String getEmployeeName(int id) {
        // 瞬間從幾萬筆資料中找到對象，不需要像 List 一樣跑迴圈
        return employeeCache.getOrDefault(id, "Unknown");
    }
}
```

## 📊 實務對照與選用表

| 特性 | Array | ArrayList | HashMap |
| :--- | :--- | :--- | :--- |
| **大小** | 固定 | 動態 (Dynamic) | 動態 (Dynamic) |
| **存取速度** | 最快 $O(1)$ | 極快 $O(1)$ | 極快 $O(1)$ |
| **搜尋速度** | 慢 $O(n)$ | 慢 $O(n)$ | **最強 $O(1)$** |
| **新增/刪除** | 不支援（須重建） | 中等（底部新增快，中間刪除慢） | 快 $O(1)$ |
| **主要用途** | 效能底層、常數定義 | 大量資料集、序列化處理 | 快取 (Cache)、關聯查找 |

## 🛠️ 開發者的選用決策邏輯 (Decision Flow)

1. **你知道資料總量嗎？且這輩子都不會變？**
   - 是 ➡️ **Array**
   - 否 ➡️ 往下看

2. **你是要拿來「存一群資料」並「逐一處理」嗎？**
   - 是 ➡️ **ArrayList**

3. **你是要透過「某個關鍵字 (Key)」來快速「找到對象」嗎？**
   - 是 ➡️ **HashMap**

4. **你需要頻繁在中間插入或刪除元素嗎？**
   - 是 ➡️ **LinkedList** (雖然 ArrayList 較常用，但 LinkedList 在特定頻繁刪改下有優勢)

## 4. 延伸疑問解答 (FAQ)

### ❓ Q1：為什麼寫成 `List<String> list = new ArrayList<>()` 模式？
**觀念：介面 (Interface) vs. 實作 (Implementation)**
- **List** 是 Interface（合約）：定義了身為一個清單「應該」具備什麼功能（如：add, remove）。
- **ArrayList** 是 Class（實作）：定義了具體「怎麼做」（用連續記憶體來存）。
- **優點**：這叫「依賴抽象」。如果未來資料量太大，想把 `ArrayList` 換成 `LinkedList`，你只需要改 `new` 後面的部分，前面的所有邏輯代碼（List 變數）都不需要更動。

### ❓ Q2：泛型 `<>` 裡面的型態數量，為什麼 List 只有一個，Map 要兩個？
- **List <T>**：清單的結構是一維序列。就像一列火車，你只需要知道這列火車運的是什麼（String 或 Integer）。
- **Map <K, V>**：對應表的架構是「標籤 (Key) ➡️ 內容 (Value)」。就像字典，你必須有「字詞」才能找到「解釋」。所以它強制要求兩個型態標註。

### ❓ Q3：實務常聽到的「批次處理 (Batch Processing)」是什麼？
批次處理是將任務「集結成堆」後再一次性處理。這與「即時處理」相對。

#### **🏥 醫院實務案例：**
- **日結報表**：每天晚上 12 點，系統一次統計當天所有診間的掛號費，而不是每掛號一人就跑一次全局報表。
- **健保申報**：以「月」或「週」為單位，將上萬筆病患資料整合成一個大檔案上傳。

#### **💻 程式實作層級：**
在 Java 中，我們通常使用 **ArrayList** 來當作批次處理的「容器」：
1. 先建立一個 `List<Order> orders = new ArrayList<>();`。
2. 在迴圈中把 1000 筆資料 `orders.add(order)` 進去。
3. 最後呼叫資料庫的 `db.executeBatch(orders)`。
   - **為什麼不一筆筆存？** 敲 1000 次資料庫的門會讓效能崩潰；載一整箱資料敲 1 次門，效率提升數十倍。
