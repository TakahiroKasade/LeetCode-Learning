# 20260420 OOP 核心觀念導引：類別、物件與記憶體

在本週的啟動過程中，我們針對 Java 物件導向 (OOP) 的基礎進行了深入討論，以下是今日的重點整理與實務思考。

## 1. 引用型別 vs 數值型別 (Type System)

| 特性 | 數值型別 (Primitive) | 引用型別 (Reference) |
| :--- | :--- | :--- |
| **包含成員** | `int`, `double`, `boolean`, `char` 等 | `String`, `Patient`, `Object`, 陣列 |
| **記憶體位置** | 直接存放在 **Stack (棧)** 中 | 地址存於 Stack，實體存於 **Heap (堆)** |
| **預設值** | `0`, `0.0`, `false` | **`null`** |
| **效能** | 較高，佔用空間固定 | 較低，需透過地址尋找實體 |

## 2. 記憶體地址與 HashCode

- **HashCode 的本質**：每個 Java 物件產生時，JVM 都會分配一塊記憶體空間。`hashCode()` 方法預設會返回一個與該記憶體地址相關的整數。
- **動態性**：地址不是固定的，每次程式執行時，JVM 都會重新分配。
- **屬性影響**：增加類別的屬性會增加物件在 Heap 中占用的長度，但不會改變物件本身的地基地址。

## 3. 存取權限與賦值 (Access Modifiers)

- **預設權限 (Package-private)**：當變數前未加上 `public` 或 `private` 時，同一個 Package 內的類別可以互相點選存取。
- **直接賦值 vs 封裝**：
    - 直接賦值：`p1.age = 20;` (容易產生無效資料)
    - 封裝存取：`p1.setAge(20);` (可在方法內加入邏輯判斷，明天進階練習重點)

## 🏥 醫學資訊系統 (HIS) 實務思考

### 議題：病人年紀該用什麼型別？

- **`int age`**：
    - 優點：節省空間，直接進行數值運算（如分層統計）。
    - 缺點：預設值為 `0`，無法區分是「剛出生或是資料未填」。
- **`Integer age` (引用型別)**：
    - 優點：預設值為 `null`，可明確代表「未領取到資料」。
- **`String age`**：
    - 優點：資料庫相容性最高（許多 legacy DB 用 VARCHAR 存所有東西）。
    - 缺點：需要頻繁轉換，且容易混入非數字字元導致系統出錯。

> [!IMPORTANT]
> **今日金句**：類別是藍圖，物件是房子；寫程式是為了蓋出能安全住人的房子，不只是畫畫圖而已。
