# SQL 進階：UNION 集合運算與複雜查詢 (2026/04/23)

## 📌 核心觀念
在資料庫中，當我們需要將兩個不同的查詢結果「垂直」合併時，就會使用集合運算子。

| 運算子 | 說明 | 效能 |
| :--- | :--- | :--- |
| **UNION** | 合併結果集，並 **自動移除重複** 的列。 | 較慢 (需比對重複) |
| **UNION ALL** | 合併結果集，**保留重複** 的列。 | 較快 (直接合併) |

---

## 📊 資料庫結構參考 (HIS Schema)
在寫題目之前，請參考以下欄位定義：

1. **Patients (病人表)**: `patientId`, `patientName`, `age`
2. **Registration (掛號紀錄表)**: `regId`, `patientId`, `dept`, `shift`, `regDate`
   - *註：dept 包含 'Internal Medicine' (內科), 'Surgery' (外科)*
   - *註：shift 包含 'Morning' (上午診), 'Afternoon' (下午診)*
3. **Doctors (醫師表)**: `doctorId`, `doctorName`, `dept`

## 🛠️ 實戰練習題

### 題目 1：跨科別掛號名單 (UNION)
**情境**：主管想知道所有曾掛號過「內科 (Internal Medicine)」或「外科 (Surgery)」的病人姓名。請確保同一個病人即使掛了兩科，在清單中也只出現一次。

```sql
-- 請在此處撰寫你的 SQL
```
SELECT  p.patientName
FROM Patients p
JOIN Registration r ON  p.patientId = r.patientId
WHERE r.dept = 'Internal Medicine'

UNION

SELECT  p.patientName
FROM Patients p
JOIN Registration r ON  p.patientId = r.patientId
WHERE r.dept = 'Surgery'

---

### 題目 2：掛號流水帳 (UNION ALL)
**情境**：財務部需要一份「掛號日誌」，列出所有掛號紀錄的流水帳。即使同一個人在同一天掛了兩次號，也要完整呈現。請合併「上午診」與「下午診」的掛號資料。

```sql
-- 請在此處撰寫你的 SQL
```
SELECT  patientId, dept, regDate
FROM Registration 
WHERE shift = 'Morning'

UNION ALL 

SELECT  patientId, dept, regDate
FROM Registration 
WHERE shift = 'Afternoon'

---

### 題目 3：綜合挑戰 (UNION + JOIN + Subquery)
**情境**：找出所有「年齡 > 60 歲的病人姓名」以及「主治醫師為 '吳依弘' 的病人姓名」，並將結果依姓名排序。

**提示**：
1. 第一個 SELECT 處理年齡篩選。
2. 第二個 SELECT 處理醫師名稱篩選（可能需要 JOIN 醫師表）。
3. 最後使用 `ORDER BY` 進行排序。

```sql
-- 請在此處撰寫你的 SQL
```
SELECT  patientName
FROM  Patients
WHERE age >60 

UNION

SELECT  p.patientName
FROM  Patients p
JOIN Registration r ON p.patientId = r.patientId
JOIN Doctors d on d. doctorId = r.doctorId 
WHERE d.doctorName = '吳依弘'  
ORDER BY patientName

## 💡 Takahiro 的思考區
*   **思考題**：為什麼在處理大數據（如數百萬筆醫療紀錄）時，如果確定資料不會重複，工程師通常會優先選擇 `UNION ALL`？
*   **我的答案**：因為 大型醫療紀錄 都需要保存 ,但可能某幾個欄位重複 也要保留,以免未來法律追究!
*   **AI 補充 (技術層面)**：因為 `UNION` 會觸發資料庫的「去重 (Distinct)」機制，這涉及大數據的排序與比對，非常耗費 CPU 與記憶體；而 `UNION ALL` 只是單純的結果集串接，效能極高。在確保資料邏輯不衝突的情況下，`UNION ALL` 是大數據處理的首選。
