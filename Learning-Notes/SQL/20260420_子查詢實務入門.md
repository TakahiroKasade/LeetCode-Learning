# 20260420 SQL 進階：子查詢 (Subquery) 實務入門

子查詢是 SQL 指令中的「俄羅斯娃娃」，在一個查詢內嵌套另一個查詢，用來解決需要多次篩選的複雜問題。

## 1. 使用場景：WHERE 中的子查詢

當你的篩選條件並非一個固定的值，而是需要從資料庫「即時計算」出來時，就必須使用子查詢。

### 🏥 醫學實務情境：
**需求**：找出所有跟病人 'P001' (張小明) 在同一個「科別」看診的其他病人。
**邏輯**：
1. 先查出 'P001' 是哪個科。
2. 再查出全院有哪些人也在該科。

```sql
SELECT PatientName 
FROM Patients 
WHERE DeptID = (SELECT DeptID FROM Patients WHERE PatientID = 'P001');
```

## 2. 今日挑戰：全公司薪水精英榜

**題目**：
有一張員工表 `Employees`，包含 `Name` 與 `Salary`。請找出薪水**高於公司平均薪水**的所有員工。

### 我的練習區：
(請在此處寫下你的 SQL)

---  
SELECT Name, Salary
FROM Employees 
WHERE Salary > (SELECT AVG(Salary) FROM Employees)

**題目**：
找出全公司薪水排名前三名的人所屬的科別有哪些？

### 💡 進階解法：當子查詢傳回多筆資料時
當我們的子查詢會傳回超過一筆資料時（例如前三名的薪水），外層的 `WHERE` 不能使用 `=`，必須改用 **`IN`**。

```sql
SELECT DISTINCT DeptID 
FROM Employees 
WHERE Salary IN (
    SELECT Salary 
    FROM Employees 
    ORDER BY Salary DESC  
    LIMIT 3
);
```
*註：使用 `DISTINCT` 是為了過濾重複出現的科別。*

### 挑戰 1：高齡病人篩選
**題目**：找出所有「年紀大於 **心臟科 (DeptID='HEART') 平均年紀**」的病人姓名。
- **拆解步驟**：
    1. 先求出心臟科病人的平均年紀。
    2. 外層過濾年紀大於該數值的病人。

SELECT Name
FROM Patients
WHERE AGE > (SELECT AVG(AGE) FROM Patients WHERE DeptID='Heart');

### 挑戰 2：薪資與病人關聯
**題目**：找出所有「主治醫師薪水 **高於 10 萬**」的所有病人姓名。
- **拆解步驟**：
    1. 先找出薪水 > 100,000 的醫師 ID 清單。
    2. 從掛號表 (`Appointments`) 比對出病人 ID 並找出姓名。
步驟一:找出薪水>100000的醫師ID清單
SELECT DoctorID FROM Doctors  WHERE Salary>100000
步驟二:從掛號表 (`Appointments`) 比對出病人 ID 並找出姓名。
SELECT  PatientID FROM  Appointments  WHERE DoctorID in  (SELECT DoctorID FROM Doctors  WHERE Salary>100000); 
步驟三:找出所有「主治醫師薪水 **高於 10 萬**」的所有病人姓名。
SELECT  Name FROM  Patients WHERE  PatientID in (SELECT  PatientID FROM  Appointments  WHERE DoctorID in  (SELECT DoctorID FROM Doctors  WHERE Salary>100000));

### 挑戰 3：邊緣病人檢查 (反向思考)
**題目**：找出所有「 **從未有過** 掛號紀錄 (`Appointments`)」的病人姓名。
- **提示**：使用 `NOT IN` 來比對 `PatientID`。

步驟一:找出所有有掛號紀錄的病人ID
SELECT PatientID FROM Appointments;
步驟二:找出所有「 **從未有過** 掛號紀錄 (`Appointments`)」的病人姓名。
SELECT Name
FROM  Patients 
WHERE  PatientID NOT IN {
		SELECT  PatientID 
		FROM  Appointments  
};

SELECT PatientID FROM Appointments;

## 3. 重要筆記：子查詢的限制

1. **傳回值的數量**：
    - 如果外層使用 `=`，子查詢必須只能傳回 **「單一欄位的單一數值」**。
    - 如果子查詢傳回多筆資料，外層必須改用 **`IN`**。
2. **效能考量**：
    - 資料量極大時，子查詢可能比 `JOIN` 慢，但在邏輯層次上，子查詢通常更容易閱讀。
